HDSF v0.1.0 guide

Using HDSF

Three ways to use HDSF, from lightest to fullest.

1. Read and tick

Read the core rules and the profiles that fit your product, then tick the self-assessment checklist. Keep evidence next to each tick. No tools needed.

2. Describe your product

Copy templates/hdsf.yaml to the root of your repository and fill it in. It takes about an hour and answers most questions a reviewer, a buyer or an authority will ask first: the intended purpose, the device question, where data goes, who receives health data, and which documents exist.

3. Run the scanner

git clone https://github.com/eduardon83/Digital-health-safety-framework hdsf
pip install pyyaml
python3 hdsf/tooling/scan.py --repo path/to/your/product --level 1 --out-dir hdsf-report --format md,json,sarif

Without code (for designers, product owners or buyers who have only the documents):

python3 hdsf/tooling/scan.py --repo path/to/folder-with-hdsf.yaml --description-only

Reading the report

SeverityMeaning
BLOCKA MUST rule with a strong sign of a problem. Fix it before launch.
REVIEWA MUST rule with a sign that needs a person to decide.
WARNA SHOULD rule with a sign. Fix it or record why not.
HUMANA rule that applies but only a person can check. Keep the evidence.
WAIVEDA finding covered by an inline comment or a dated waiver.

Automated checks find signs, not proof. A clean report does not mean a product is compliant.

In CI

Add the scan to your pipeline and fail on blocking findings:

python3 hdsf/tooling/scan.py --repo . --level 1 --fail-on block --format sarif --out-dir hdsf-report

Upload hdsf-report/hdsf.sarif to GitHub code scanning to see findings next to the code. Semgrep users can also use tooling/semgrep/hdsf.yml.

Ignoring a finding

When a finding is wrong, add a comment on the line or the line above, with a reason:

console.log("condition picker opened"); // hdsf-ignore: CORE-DAT-10 because no health value is logged

For a whole rule, add a dated waiver in hdsf.yaml:

waivers:
  - {rule: CORE-SEC-05, reason: "SBOM pipeline ships in March", until: 2027-03-31}

With Claude

The skill/hdsf-review/ folder is a skill for Claude. It runs the scanner, reads the report with you and drafts the missing documents (qualification record, DPIA outline, AI inventory).

The engine

HDSF runs on the Safety Framework Engine (engine/sfe), shared with the Child-Safe EdTech Framework. The engine lives in the CSEF repository; HDSF keeps a pinned copy and records the commit in engine/ENGINE.lock.
